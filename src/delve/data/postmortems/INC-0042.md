# Postmortem: INC-0042

**Service:** payment-service
**Date:** 2026-05-14
**Severity:** High

## Summary
Payment service 5xx errors spiked to 22% following deployment of v2.1.0.
Root cause was a database connection pool misconfiguration — pool_size
was accidentally set to 8 instead of the intended 40 during a config
refactor, causing pool exhaustion under normal traffic within minutes
of deployment.

## Timeline
- 09:00 - Deployment v2.1.0 completed
- 09:04 - DB pool utilization crossed 90%
- 09:09 - First connection timeout errors logged
- 09:15 - Error rate peaked at 22%
- 09:30 - Rolled back to v2.0.9, pool_size restored to 40

## Root Cause
Config refactor merged a wrong default value for `db_pool_size` from a
staging environment template.

## Resolution
Rollback + pool_size correction. Added a config validation step to CI
that flags any pool_size change greater than 20% from the previous value.

## Lessons Learned
Database connection pool sizing should be treated as a protected
configuration value with mandatory review on any change.
